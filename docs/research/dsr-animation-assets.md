# DARK SOULS REMASTERED 애니메이션 자산 조사

## 1. 조사 목적

본 조사는 DARK SOULS REMASTERED PvP 교육 영상 편집기에서 이동, 공격, 뒤잡기 연출을 실제 게임의 동작과 가깝게 재현할 수 있는지 확인하기 위한 것이다. 게임 원본을 수정하거나 재배포 가능한 자산 묶음을 만드는 것이 목적이 아니다.

조사일은 2026년 8월 27일이며, 설치 경로는 다음과 같다.

```text
C:\Program Files (x86)\Steam\steamapps\common\DARK SOULS REMASTERED
```

## 2. 취급 원칙

- Steam 게임 설치 폴더는 읽기 전용으로 조사했다.
- 분석 대상은 `D:\3D-render\local-assets\raw\dsr\chr`에 복사한 사본이다.
- 원본 및 추출 파일은 `.gitignore`의 `local-assets/` 규칙으로 Git에서 제외한다.
- 외부 도구는 `D:\3D-render\tools`에서 관리하며 Git에 포함하지 않는다.
- 프로젝트 저장소에는 파일명, 구조, 개수, 체크섬, 변환 절차와 조사 결론만 기록한다.
- 게임 자산을 실행 파일이나 배포 패키지에 포함하지 않는다.

## 6. TAE 분석과 확인된 도구 제한

`taeNew\x64\a00.tae`를 XML로 직렬화해 애니메이션 ID와 이벤트 시간을 확인했다.

처음에는 종료 코드 `-1`만 반환됐다. WitchyBND 3.0.1.0 소스를 확인한 결과 자동 게임 판별 목록에 DARK SOULS REMASTERED 실행 파일이 없어, 복사된 경로를 수동 입력이 없는 `--passive` 모드에서 DS1R 형식으로 결정하지 못한 것이 첫 번째 원인이었다. 로컬 분석 루트의 `project.json`에 `GameType: 3`을 기록해 DS1R 형식을 명시했다.

그 후 74개 애니메이션 XML 파일이 생성됐지만 종료 코드는 여전히 `-1`이었다. 단일 스레드와 터미널 출력으로 재현한 실제 예외는 다음과 같다.

```text
System.ArgumentException: hexadecimal value 0x01, is an invalid character.
```

문제 항목은 `anim-000030.xml`의 `<name>` 값에 포함된 XML 금지 제어문자다. 이 때문에 해당 파일은 일부만 기록되고 `_witchy-tae.xml` 최종 매니페스트가 만들어지지 않는다. 나머지 73개 애니메이션 XML은 생성되며, 원본 TAE나 HKX가 손상됐다는 뜻은 아니다. WitchyBND의 XML 출력 계층이 해당 문자열을 그대로 기록하지 못하는 호환성 문제다.

현재 결과 경로는 다음과 같다.

```text
D:\3D-render\local-assets\extracted\witchy\c0000-base-nonrecursive
D:\3D-render\local-assets\extracted\witchy\player-animation-bundles
D:\3D-render\local-assets\extracted\witchy\tae-analysis
```

## 7. 현재 결론

- 이동, 공격, 뒤잡기 재현에 활용할 수 있는 플레이어 스켈레톤, HKX 애니메이션 클립, TAE 이벤트 데이터가 실제 설치 파일 안에 있다.
- 원본에서 바로 Godot용 애니메이션으로 사용할 수는 없다. HKX를 읽고 스켈레톤과 함께 표준 교환 형식으로 변환하는 단계가 필요하다.
- TAE의 숫자 ID만으로 동작 의미를 확정하면 안 된다. 애니메이션을 뷰어에서 재생해 이동, 무기군별 공격, 공격자 뒤잡기, 피격자 뒤잡기 쌍을 확인해야 한다.
- 뒤잡기는 공격자와 피격자의 동기화 애니메이션, 기준 루트 위치, 시작 방향, 타격 이벤트 시점을 하나의 세트로 관리해야 한다.
- 실제 게임 자산은 선택적 로컬 입력으로만 취급한다. 편집기 기본 배포본은 자체 제작 플레이스홀더 캐릭터와 애니메이션으로도 실행 가능해야 한다.

## 8. 다음 조사 단계

1. TAE XML 제어문자 문제를 우회하는 읽기 전용 분석기를 `tools/` 아래에 만든다.
2. 모든 TAE에서 애니메이션 ID, HKX 참조, 지속 시간, 이벤트 종류와 구간을 CSV 또는 JSON 인덱스로 생성한다.
3. HKX를 시각적으로 확인할 수 있는 오픈 소스 도구의 DSR 지원 여부와 라이선스를 검증한다.
4. 이동·대기·회피·무기군별 공격 후보를 분류한다.
5. `c0000_c####` 묶음에서 공격자/피격자 뒤잡기 후보 쌍을 찾고 루트 모션 정렬을 검증한다.
6. 확인된 ID를 편집기 내부의 의미 기반 이름과 매핑하되, 원본 파일은 계속 로컬에만 둔다.
