# 3D PvP 교육 영상 편집기 아키텍처 설계 명세

## 문서 상태

- 작성일: 2026년 8월 27일
- 대상: Windows 11 오프라인 독립 실행 프로그램
- 기준 작업 경로: `D:\3D-render`
- 기준 엔진: Godot 4.7.2 Stable .NET
- 기준 렌더러: Forward+
- 주 언어: C#

## 문제 정의

사용자는 DARK SOULS REMASTERED PvP 교육용 영상에서 전투 참여자의 시간별 위치, 방향, 락온, 이동 경로, 공격과 뒤잡 관계를 명확히 보여주고 싶다. 기존 탑뷰 가이드는 정확한 2D 좌표와 규칙 평가를 제공하지만 입체적인 움직임, 실제 애니메이션과 카메라 연출을 표현하기 어렵다. 범용 3D 도구는 이 작업에 과도하게 복잡하며 동일한 전투 규칙을 반복 적용하기 어렵다.

본 설계는 탑뷰의 분석 정확성과 3D 프리뷰·렌더를 하나의 문서에서 결합하는 전용 편집기를 정의한다.

## 확정된 제품 결정

1. Windows 11만 공식 지원한다.
2. 편집기 런타임은 완전 오프라인으로 동작한다.
3. 탑뷰와 3D 뷰는 동시에 표시하고 같은 문서를 편집한다.
4. Godot 4.7.2 Stable .NET과 C#을 사용한다.
5. Forward+를 기본 렌더러로 사용한다.
6. `SceneDocument`를 단일 진실 공급원으로 사용한다.
7. 위치·전투 계산은 Godot에 의존하지 않는 도메인 계층에 둔다.
8. 편집 변경은 명령 기반 Undo/Redo를 사용한다.
9. 내부 저장은 버전형 JSON이며 원자적 저장과 마이그레이션을 지원한다.
10. 영상은 결정적 프레임 평가 후 이미지 시퀀스와 FFmpeg 인코딩으로 출력한다.
11. 실제 DSR 자산은 로컬 선택 입력이며 Git·배포본에서 제외한다.
12. 실제 자산 없이도 플레이스홀더로 모든 핵심 기능을 실행할 수 있어야 한다.

## 사용자 경험 목표

사용자는 기존 탑뷰 장면을 불러온 직후 네 캐릭터와 이동 경로를 두 뷰에서 확인한다. 탑뷰에서 위치를 정밀 조정하고 3D에서 높이·카메라·동작을 조정한다. 공격 시점에는 공격 표시와 뒤잡 오버레이가 나타나고, 타임라인을 재생해 전술 흐름을 확인한다. 마지막으로 같은 장면 데이터를 텍스트 가이드와 영상으로 출력한다.

## 아키텍처 결정 기록

### Godot 대 Unity 대 Blender

Godot은 설치·배포 구조가 단순하고 2D와 3D UI를 한 실행 파일에서 결합하기 쉬우며 오픈 소스다. Unity는 풍부한 생태계가 있지만 본 프로젝트 규모에서 에디터·라이선스·패키지 복잡도가 더 크다. Blender는 자산 검수와 변환에는 강하지만 DSR 전투 데이터 전용 UI를 일반 사용자용 독립 앱으로 제공하기에는 불필요한 기능과 조작 복잡도가 많다. 따라서 Godot을 런타임, Blender를 선택적 자산 도구로 사용한다.

### GDScript 대 C#

좌표·보간·판정·직렬화와 테스트 가능한 도메인 모델이 중요하므로 C#을 선택한다. Godot 장면 연결에도 C#을 사용해 언어 경계를 줄인다. 성능이 증명된 일부 렌더 보조 스크립트에만 GDScript를 허용할 수 있으나 기본 선택은 아니다.

### 모듈식 모놀리스 대 다중 프로세스

오프라인 독립 실행과 복구 단순성을 위해 하나의 앱을 사용한다. FFmpeg와 선택적 자산 변환기만 통제된 자식 프로세스로 실행한다. 내부 기능을 네트워크 서비스로 나누지 않는다.

### 두 뷰 상태 동기화

탑뷰 노드의 값을 3D 노드로 복사하거나 반대로 복사하지 않는다. 두 뷰가 같은 문서 스냅샷을 투영한다. 이 결정은 순환 갱신, 미세 오차와 저장 시점 불일치를 막는다.

### 실제 게임 애니메이션

프로그램 기능과 자산을 분리한다. `ActionKey`는 의미 이름이고 `AssetCatalog`가 플레이스홀더 또는 로컬 DSR 클립을 선택한다. 자산이 없어도 문서는 유효하며, 자산 경로는 가능한 한 프로젝트 외부 로컬 카탈로그에 둔다.

## 중요 불변 조건

- 문서 안의 모든 배우 ID는 고유하다.
- 같은 트랙에 동일 시간 키프레임이 두 개 존재하지 않는다.
- 시간은 유한한 숫자이며 0 이상, 문서 길이 이하이다.
- 위치와 각도에 NaN 또는 Infinity를 저장하지 않는다.
- 락온 대상은 존재하는 다른 배우다.
- 뒤잡 반경·길이·임계값은 음수가 아니며 임계값은 0~1 범위다.
- 동기화 행동 그룹의 참여자는 같은 기준 시작 시간을 공유한다.
- 저장·렌더 시 사용하는 문서 스냅샷은 작업 중 변경되지 않는다.

## 정확성 수준

시각화에는 서로 다른 정확성 상태를 표시한다.

- `EducationalApproximation`: 사용자가 제공한 110°/60%/접촉 규칙 같은 교육용 근사
- `Measured`: 실제 영상·프레임 또는 실험에서 측정된 값
- `GameDataMapped`: 게임 데이터 이벤트와 애니메이션 매핑까지 확인된 값
- `VerifiedScenario`: 사용자가 특정 장면 결과를 정상으로 재확인하고 Git 태그로 고정한 버전

화면과 보고서에서 교육용 근사를 실제 엔진의 완전한 내부 판정으로 표현하지 않는다.

## 렌더 결정성

렌더 프레임 `n`의 시간은 `start + n / fps`로 계산한다. 엔진의 가변 `delta`를 누적하지 않는다. 물리 효과가 필요하면 고정 스텝과 초기 상태를 사용한다. 랜덤 효과에는 문서에 저장된 시드를 사용한다. 같은 문서·버전·자산 카탈로그·렌더 설정은 같은 의미 프레임을 만들어야 한다.

## 데이터 보존

가져온 원본 파일의 경로, 형식, 해시와 변환 설정을 기록한다. 원본은 수정하지 않는다. 저장 실패 시 기존 파일을 그대로 두며 임시 파일은 복구 진단용으로 구분한다. 자동 저장은 사용자 저장 파일과 별도 폴더에 보관한다.

## 네트워크 경계

앱 런타임에는 서버, 계정, 소켓, HTTP API, 원격 데이터베이스가 없다. GitHub는 개발 소스 버전 관리에만 사용하며 릴리스 앱의 기능 의존성이 아니다. 업데이트 확인도 기본 제공하지 않는다. 외부 자산과 도구는 사용자가 명시적으로 준비한 로컬 경로에서 읽는다.

## 완료 정의

아키텍처 구현이 완료됐다고 판단하려면 V1 샘플 가져오기, 동시 뷰 편집, 보간, 락온, 판정 시각화, 저장 왕복과 결정적 렌더가 자동·수동 검증을 통과해야 한다. 모든 배포 산출물에 게임 원본 자산과 개발자 개인 경로가 없어야 하며, Windows 11의 깨끗한 오프라인 환경에서 실행돼야 한다.
