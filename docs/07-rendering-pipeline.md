# 07. 렌더링 파이프라인

## 목표

편집 미리보기의 순간 프레임률과 관계없이 같은 문서와 렌더 설정에서 같은 시간 샘플을 출력한다. 긴 렌더가 인코딩 단계에서 실패해도 이미 만든 프레임을 잃지 않고 다시 인코딩할 수 있어야 한다.

## 파이프라인

```text
문서 검증
→ 읽기 전용 렌더 스냅샷
→ 자산 해석 및 누락 대체
→ 프레임 시간 목록 생성
→ Godot Movie Maker 이미지 시퀀스
→ 프레임 개수·해상도 검증
→ FFmpeg 인코딩
→ 최종 파일 검사
→ 작업 보고서 기록
```

## 렌더 설정

- 출력 폴더
- 파일 기본 이름
- 시작·종료 시간
- FPS
- 해상도와 화면 비율
- 투명 배경 여부
- 카메라 트랙
- 탑뷰/3D/분할 화면 출력 모드
- 오버레이 포함 설정
- 안티앨리어싱·그림자·후처리 품질
- 이미지 형식과 인코더 프리셋
- 오디오 포함 여부는 후속 범위로 분리

## 프레임 시간

종료 시간을 포함할지 정책을 고정한다. 권장식은 `[start, end)` 반개구간이다.

```text
frameCount = ceil((end - start) * fps)
time(n) = start + n / fps, 0 <= n < frameCount
```

프레임 번호는 0 또는 1부터 시작하는 고정 자릿수 파일명으로 출력한다. 부동소수점 누적 대신 프레임 인덱스에서 시간을 직접 계산한다.

## 렌더 스냅샷

렌더 시작 시 문서 내용, 자산 카탈로그 해시, 엔진 버전과 설정을 고정한다. 렌더 중 사용자가 편집하더라도 진행 중 작업은 바뀌지 않는다. 작업 보고서에 다음을 기록한다.

- 문서 ID와 리비전
- 렌더 작업 ID
- 시작 일시와 완료 상태
- Godot·프로그램·FFmpeg 버전
- 자산 카탈로그 ID/해시
- 설정과 예상 프레임 수
- 실제 생성 프레임 수
- 경고와 오류

## 미리보기와 최종 품질 분리

미리보기는 반해상도, 낮은 그림자, 제한된 궤적 샘플과 단순 재질을 사용할 수 있다. 최종 렌더는 원본 해상도, 고품질 안티앨리어싱과 지정된 오버레이 품질을 사용한다. 품질 설정은 문서 의미와 판정 결과를 바꾸지 않는다.

## FFmpeg 연결

FFmpeg는 인자 배열로 실행하고 사용자 입력을 하나의 셸 문자열로 이어 붙이지 않는다. 실행 파일 경로는 `tools/` 또는 사용자가 확인한 절대 경로만 허용한다. 기본 영상은 Windows 호환성을 고려해 H.264/AAC MP4 프리셋을 제공할 수 있으며 라이선스와 배포 방식을 별도로 검토한다.

인코딩 단계는 이미지 렌더와 독립 작업이다. 실패 시 다음 정보를 제공한다.

- 종료 코드
- 표준 오류의 제한된 로그
- 입력 프레임 패턴
- 실행한 안전한 인자 목록
- 재시도 가능한 명령 프리셋

## 진행률과 취소

렌더 진행률은 `완료 프레임 / 전체 프레임`으로 계산한다. 취소 요청 시 현재 프레임 쓰기를 안전하게 마치고 작업을 `Cancelled`로 표시한다. 이미지 시퀀스를 삭제할지는 사용자 선택이며 자동으로 지우지 않는다.

FFmpeg 취소는 정상 종료 신호를 먼저 보내고 제한 시간 후 자식 프로세스만 종료한다. 다른 FFmpeg 프로세스를 이름으로 일괄 종료하지 않는다.

## 출력 디렉터리

```text
exports\renders\<document-slug>\<render-id>\
├─ frames\
│  ├─ frame_000001.png
│  └─ ...
├─ video\
│  └─ <document-slug>.mp4
└─ render-report.json
```

경로의 문서 이름은 Windows 금지 문자를 제거한 슬러그로 만들고 실제 문서 이름은 보고서에 보존한다. 기존 작업 폴더와 충돌하면 덮어쓰지 않고 새 작업 ID를 만든다.

## 실패 복구

- 프레임 누락: 누락된 번호만 다시 렌더할 수 있는지 검사한다.
- 인코딩 실패: 프레임을 보존하고 인코딩만 재시도한다.
- 디스크 부족: 렌더 전에 예상 크기와 여유 공간을 확인하고 중간에도 감시한다.
- 자산 누락: 정책에 따라 플레이스홀더 사용 또는 작업 중단을 선택한다.
- 프로그램 종료: 보고서의 마지막 완료 프레임에서 복구 가능한 후보로 표시한다.

## 검증

- 예상 프레임 수와 실제 파일 수 일치
- 모든 이미지의 해상도와 포맷 일치
- 첫·마지막 프레임 시간의 기준 이미지 비교
- 같은 입력을 두 번 렌더했을 때 의미 상태 해시 일치
- FFmpeg 종료 코드 0과 출력 파일 존재·길이 확인
- 로컬 게임 원본 또는 개인 절대 경로가 보고서 외 배포 메타데이터에 포함되지 않는지 확인
