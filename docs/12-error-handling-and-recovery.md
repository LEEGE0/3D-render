# 12. 오류 처리와 복구

## 오류 원칙

- 사용자 문서와 원본 자산 보존이 가장 중요하다.
- 오류를 숨기고 성공처럼 진행하지 않는다.
- 사용자에게는 해결 가능한 설명을, 로그에는 진단 가능한 원인을 제공한다.
- 부분 성공과 전체 성공을 구분한다.
- 재시도 가능한 작업과 입력을 고쳐야 하는 오류를 구분한다.

## 오류 분류

| 분류 | 예 | 처리 |
| --- | --- | --- |
| 입력 검증 | 잘못된 시간, 없는 락온 대상 | 해당 변경 거부, 필드에 설명 |
| 문서 형식 | 알 수 없는 필수 버전, 손상 JSON | 원본 읽기 전용 유지, 열기 중단 |
| 자산 | 누락 HKX, 호환되지 않는 스켈레톤 | 플레이스홀더 또는 명시적 중단 |
| 파일 시스템 | 권한, 디스크 부족, 경로 충돌 | 기존 파일 보존, 다른 경로 안내 |
| 외부 도구 | FFmpeg 종료 코드 비정상 | 프레임 보존, 로그와 재시도 제공 |
| 렌더 | 프레임 누락, 장치 오류 | 작업 실패 표시, 완료 프레임 보존 |
| 내부 결함 | 예상하지 못한 예외 | 세션 복구 저장 시도, 오류 보고서 로컬 생성 |

## 결과 타입

예상 가능한 실패에 예외를 남용하지 않고 다음 의미를 표현하는 결과를 사용한다.

```text
Result<T>
├─ Success(T value, warnings[])
└─ Failure(errorCode, userMessage, technicalDetail, recoverability)
```

기술 스택 트레이스를 사용자 대화상자에 그대로 노출하지 않는다. 오류 코드와 작업 ID로 로컬 로그와 연결한다.

## 안전한 저장

1. 저장 대상의 정규화된 절대 경로와 확장자를 검증한다.
2. 같은 디렉터리에 고유 임시 파일을 만든다.
3. 완전한 JSON을 쓰고 스트림을 닫는다.
4. 임시 파일을 다시 읽어 스키마와 기본 불변 조건을 검사한다.
5. 기존 파일이 있으면 복구 정책에 따라 백업한다.
6. 같은 볼륨에서 원자적 교체를 수행한다.
7. 성공한 문서 리비전을 기록한다.

단계 1~4 실패 시 기존 파일은 건드리지 않는다. 교체 실패 시 임시 파일 위치를 알려 복구 가능하게 한다.

## 자동 저장

- 문서 변경 후 일정 유휴 시간 또는 일정 간격에 수행한다.
- UI 스레드에서 문서 스냅샷을 짧게 만들고 직렬화는 백그라운드에서 수행한다.
- 자동 저장끼리 겹치지 않으며 최신 요청을 병합한다.
- 사용자 수동 저장과 경쟁하지 않게 문서 리비전을 비교한다.
- 자동 저장 실패는 수동 저장 성공으로 오인하지 않는다.

## 비정상 종료 복구

앱 시작 시 이전 세션의 정상 종료 표식과 복구 매니페스트를 확인한다. 복구 후보마다 원본 경로, 자동 저장 시간, 원본 수정 시간과 문서 이름을 보여준다. 사용자가 열기를 선택하면 새 미저장 문서로 열고 원본을 자동 덮어쓰지 않는다.

## 가져오기 오류

가져오기는 먼저 전체 원본을 읽어 중간 표현으로 변환하고, 오류·경고 목록과 미리보기를 만든다. 치명 오류가 있으면 현재 문서를 변경하지 않는다. 경고만 있으면 사용자가 다음을 확인할 수 있어야 한다.

- 변환된 배우·키프레임 수
- 건너뛴 항목
- 알 수 없는 행동과 대체값
- 좌표 배율과 원점
- 모순된 락온 데이터

## 자산 오류와 대체

자산 카탈로그는 `Available`, `Missing`, `Unverified`, `Incompatible`, `Placeholder` 상태를 가진다. 누락 자산을 빈 화면으로 두지 않고 역할색 플레이스홀더와 의미 행동 표시를 제공한다. 동기화 뒤잡 세트의 한쪽만 있으면 실제 세트를 사용하지 않고 둘 다 대체해 어긋난 연출을 막는다.

## 외부 프로세스

- 실행 전에 파일 존재, 체크섬 또는 허용 버전, 출력 디렉터리를 확인한다.
- 표준 출력·오류를 크기 제한 로그로 수집한다.
- 종료 코드, 타임아웃, 취소를 구분한다.
- 자식 프로세스만 종료하고 시스템의 같은 이름 프로세스를 건드리지 않는다.
- 부분 출력은 작업 ID 폴더에 남기고 완료 표식을 만들지 않는다.

## 로그

로그는 로컬 데이터 루트에 날짜·세션별로 둔다. 개인정보와 전체 개인 경로는 필요 최소한으로 마스킹할 수 있게 한다. 토큰·비밀키·게임 바이너리 내용은 기록하지 않는다.

권장 필드:

- UTC와 로컬 시각
- 수준과 오류 코드
- 앱·엔진 버전
- 작업 ID와 문서 ID
- 단계와 지속 시간
- 예외 타입과 제한된 스택
- 복구 가능 여부

로그 보존 기간과 용량 상한을 두고 오래된 로그 정리는 정확한 로그 루트 안에서만 수행한다.

## 사용자 메시지 예

나쁜 예: “오류 -1”

좋은 예: “FFmpeg 인코딩이 종료 코드 1로 실패했습니다. 렌더된 300개 PNG 프레임은 보존되어 있습니다. 출력 폴더와 인코더 로그를 열거나 인코딩만 다시 시도할 수 있습니다.”

## 알려진 조사 사례

WitchyBND의 TAE 변환은 DSR 게임 자동 판별 실패와 XML 제어문자 `0x01`로 부분 출력 후 종료 코드 `-1`이 발생했다. 이 사례처럼 종료 코드만 기록하지 않고 터미널의 실제 예외, 생성 파일 수, 미완성 매니페스트와 원본 보존 여부를 함께 진단해야 한다.
