# 08. 네트워크 아키텍처

## 결론

본 프로그램의 런타임 네트워크 아키텍처는 “네트워크 없음”이다. 편집, 저장, 자산 연결, 미리보기와 렌더링에 서버·계정·클라우드·소켓이 필요하지 않다. 이는 단순히 현재 서버가 없다는 뜻이 아니라 제품 경계로 의도적으로 결정한 오프라인 아키텍처다.

## 런타임 경계

```text
┌──────────────── Windows 11 PC ────────────────┐
│                                               │
│  3D PvP Editor                                │
│  ├─ SceneDocument / UI / Renderer             │
│  ├─ Local JSON / Settings / Cache             │
│  ├─ Optional local DSR assets                 │
│  └─ Child process: FFmpeg / asset converter   │
│                                               │
└───────────────────────────────────────────────┘
                 네트워크 연결 없음
```

## 금지되는 런타임 통신

- HTTP/HTTPS API 호출
- WebSocket과 사용자 간 실시간 동기화
- 원격 데이터베이스
- 계정 로그인과 인증 토큰
- 원격 분석, 크래시 자동 업로드와 광고
- 자동 업데이트 확인
- DARK SOULS 서버 또는 게임 프로세스 네트워크 후킹
- 로컬 네트워크 자동 검색과 수신 포트

새 라이브러리를 추가할 때는 백그라운드 업데이트, 텔레메트리와 폰홈 동작이 없는지 확인한다.

## 개발 시 네트워크

GitHub 네트워크는 소스 버전 관리와 공식 도구 조사에만 사용한다. 이는 릴리스 앱 아키텍처와 분리된다.

```text
개발 PC ──SSH──> github.com:LEEGE0/3D-render.git
개발 PC ─HTTPS─> 공식 엔진/도구 배포처
```

외부 도구 다운로드 시 버전과 SHA-256을 기록한다. 설치가 끝난 뒤 일상적인 앱 실행은 인터넷을 차단해도 동작해야 한다.

## 로컬 프로세스 통신

FFmpeg 또는 자산 변환기는 네트워크 서비스가 아니라 자식 프로세스다.

- 입력·출력은 명시된 로컬 파일 경로
- 진행과 오류는 표준 출력/오류
- 인자는 배열로 전달
- 부모 프로세스가 자식 PID와 수명을 관리
- 로컬 TCP 포트를 임시 IPC로 사용하지 않음

대용량 프레임은 프로세스 파이프로 스트리밍하기보다 초기에는 파일 기반 이미지 시퀀스를 사용해 복구 가능성을 높인다.

## 방화벽과 오프라인 검증

릴리스 수용 테스트에서 다음을 확인한다.

1. 네트워크 어댑터를 비활성화한 Windows 11 환경에서 실행한다.
2. 새 문서, 가져오기, 저장, 다시 열기, 재생과 렌더를 수행한다.
3. Windows 방화벽 수신 허용 창이 나타나지 않는지 확인한다.
4. 프로세스가 수신 포트를 열지 않는지 검사한다.
5. 네트워크 실패 로그나 긴 타임아웃 없이 즉시 시작하는지 확인한다.

## 향후 네트워크 기능 요청 처리

클라우드 저장, 협업 또는 업데이트 기능이 요구되더라도 현재 실행 파일에 바로 추가하지 않는다. 별도 설계 승인과 위협 모델, 데이터 분류, 오프라인 대체 경로가 필요하다. 기본 편집기 기능은 계속 네트워크 없이 동작해야 한다.

가능한 확장 방식은 사용자가 명시적으로 실행하는 별도 동기화 도구 또는 파일 내보내기다. 문서 포맷 자체가 로컬 파일이므로 USB, 사용자 선택 클라우드 폴더나 Git LFS 외부 워크플로를 사용자가 직접 선택할 수 있다.

## 위협 모델

네트워크가 없어도 다음 로컬 경계를 보호한다.

- 악성 프로젝트의 `..` 경로로 작업 루트 탈출
- 변조된 JSON으로 과도한 메모리 할당
- 외부 도구 인자 주입
- 자산 ZIP의 경로 탈출
- 심볼릭 링크를 통한 예상 밖 파일 덮어쓰기
- 잘못된 복구 파일이 사용자 원본을 대체하는 문제

따라서 모든 파일 가져오기와 외부 프로세스 실행은 경로 정규화, 크기 상한, 확장자·매직 검증과 명시적 출력 루트를 사용한다.
